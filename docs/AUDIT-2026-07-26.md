# Complete JOCA audit — 2026-07-26

Audit of the whole system: JOCA_Brain (131 skills · 36 agents · 27 commands · 10 hooks · 8 rules · 21 scripts), JOCA_OS (backend ~4,400 lines + frontend ~7,000 lines), install/update flows, questionnaires and cross-CLI bridges. Five independent auditors (install/update · Brain components · backend · frontend · infra/hooks), findings verified in the code with file:line. Read-only — nothing was fixed in this audit.

## Executive verdict

**JOCA's doctrine is high quality and internally consistent** — rules, soul, orchestration patterns and the best skills (frontend, yagni, agent-sdk, automations) are on par with the best there is in the ecosystem. The failures are almost all concentrated in the **wiring layer**: paths that do not resolve, indexes that truncate, hooks that do not fire, documentation that diverged from the code. In one sentence: *the system knows what it should do; frequently it cannot reach the files that say so.*

The three most urgent problems:
1. **Two real security holes in JOCA_OS** (DNS rebinding → local RCE; `llm` node with tools + bypass).
2. **The update path is functionally stopped** (`origin/master` vs `main`) and the install one produces silently incomplete installations (inert hooks, uncompiled frontend, wrong ports).
3. **Half the autonomous system does not fire**: 43% of the skills invisible to the activation index, dead auto-test pipeline, guard-rails inoperative outside the JOCA repo.

## 🔴 CRITICAL (14)

### Security — JOCA_OS

**S1 · DNS rebinding nullifies the origin guard → local RCE via the browser.**
`security-fs.ts:125` + `server.ts:57-58`: the "Origin == Host" check compares the Origin against a Host the attacker controls (rebinding evil.com→127.0.0.1). GETs do not even pass through the guard. With auth OFF (the local default mode), a malicious page reads `/file-content`, `/runtime` and talks to the WS → direct input to the PTYs = arbitrary shell.
→ Validate the **Host** against an allowlist (loopback + hosts from `JOCA_HOST`/`JOCA_ALLOWED_ORIGINS`) on every method and in `verifyClient`; only then accept Origin==Host.

**S2 · The automations' `llm` node runs with ALL the tools + `bypassPermissions`.**
`automations/runner.ts:90` does not pass `noTools:true`; the provider always applies bypass. Pipeline `[http]→[llm]→[message]`: injected web content can make the model execute Bash/Write, silently (with no visible terminal). Judge, heartbeat and /optimize-objective are already correct — only this case was left out.
→ `noTools: true` in the `'llm'` case. One line.

**S3 · Auth fail-open at runtime on a VPS.**
`auth.ts:42-44,112-115`: `authEnabled()` re-reads `auth.json` on every request; if the file disappears/corrupts with the server on `0.0.0.0`, everyone becomes authenticated. The gate only runs at boot.
→ Cache "auth was configured" at startup and fail closed (401/503) after that.

**S4 · `SENSITIVE_HOME_SUBDIRS` does not protect the CLIs' own credentials.**
`security-fs.ts:64-73`: `.claude` (OAuth token!), `.claude.json`, `.codex`, `.gemini` are missing. `GET /file-content` serves them.
→ Add them to the list.

### Install/update flow

**I1 · `/update-joca` is stopped: everything points to `origin/master`, the branch is `main`.**
`update.md:49,55,103,109` · `update-joca.md:70,85,209,219` · `sync-brain.md:29-56` · `migrate.md:148-149`. `git log HEAD..origin/master` dies with *unknown revision*.
→ Global `master`→`main` (or resolve via `git symbolic-ref refs/remotes/origin/HEAD`).

**I2 · Installation produces silently incomplete setups.** Four combined causes:
- Wrong ports throughout the onboarding: the docs say 7371/7381; the real ones are **7491/7492** (`install.md:942-1018`, `migrate.md:424-426`, `JOCA_OS/CLAUDE.md:31-35`).
- The example JSON block uses a `<BRAIN>` placeholder that the substitution step (`<JOCA_ROOT>`) does not handle (`install.md:888-929`) → hooks that fail silently.
- `sed -i ''` labeled "macOS/Linux" is BSD syntax — it fails on Linux; `$0` does not resolve in an agent session (`install.md:853-855`).
- **The frontend is never compiled** (`install.md:955-967`, `update-joca.md:269-271`): VPS/PWA mode is left with no `dist/` to serve.
→ Normalize the ports; paste the literal `settings.json`; substitution via `node -e` + `git rev-parse --show-toplevel`; add `npm run build` to the install and to the update.

**I3 · `origin: local` protection semantically broken.**
15 **official upstream** skills carry `origin: local` (joca-os-windows, cloudflare-dns, woocommerce-elementor, …) → they are frozen forever by `/update-joca`. Worse: `upgrade-joca.md:234` also marks `origin: local` on an `IMPROVE_SKILL` of upstream skills — each local improvement freezes the skill against future updates. And the "protection" of `soul.md`/`settings.json` is declarative: they are git-tracked files that the install modifies → a stash conflict on every pull.
→ A new marker exclusive to local creation (`origin: user`); clean `origin: local` out of the published files; separate template/instance (soul.template.md + gitignore of the instance).

**I4 · `migrate.md` is dangerous: it describes a layout that no longer exists and does `rm -rf` with no guard.**
`migrate.md:15-38,117-129`: it assumes `.claude/` at the root (pre-JOCA_Brain), deletes files at the wrong root, references a nonexistent `v1-legacy` branch and soul placeholders with the wrong names (`<USER_NAME>` vs `<YOUR_NAME>`).
→ Rewrite it for the current layout with gates per destructive block, or archive the command.

### Skill activation system (Brain)

**B1 · 43% of the skills are invisible to the activation system.**
`build-skill-index.py:70,91,107`: it only reads the frontmatter's `triggers:` field (56/131 skills do not have it → `triggers: []`), cuts at 10 triggers (75 truncated entries) and at 200 chars of description (128/167 cut in the middle of the triggers). The `task-router` and the `/goal` compute the ≥60% match **from this index**.
→ Extract triggers from the description ("MUST be invoked when…"), remove the caps, read `metadata.category` (today: 131 skills in the "general" category).

**B2 · `/create-skill` produces invisible skills.**
`create-skill.md:116-172` tells you to write in `skills/created-skills/<n>/SKILL.md` and claims it is "auto-discovered" — false: the indexer's glob is non-recursive (`build-skill-index.py:77`) and CLAUDE.md requires flat depth-1. Every skill created by the official pipeline is born outside the index.
→ Align: write flat + reindex (or a recursive glob — pick one).

**B3 · 61 `rules/*.md` references on a path that does not resolve (30 files).**
The real directory is `.claude/rules/`. It includes the **task-router's mandatory Step 0** (`task-router.md:27,35`) and the `/goal` (`goal.md:22`) → the classifier always falls into the heuristic fallback.
→ Global substitution `rules/` → `.claude/rules/`. Mechanical, 10 minutes.

### Hooks / autonomous loop

**H1 · The auto-test pipeline is dead end to end.** Three independent failures:
- `auto-test-dispatch.js:32` prints the recommendation to the stdout of a **Stop** hook — which is never injected into the model's context. The doctrine "Stop reads and recommends testers → dispatch without asking" does not happen.
- `check-skill-paths.sh` (settings.json:62) receives `"$TOOL_INPUT_FILE_PATH"` — a variable Claude Code does not define → a no-op on every OS.
- `stop-checkpoint.js:20-22` reads the queue in `cwd/.joca/` but `track-changes.js:19-21` writes it in `<JOCA_Brain>/.joca/` → auto-checkpoints almost never fire.
→ Stop hook with `{"decision":"block","reason":"AUTO-TEST: …"}`; stdin wrapper for the .sh; unify the queue path.

**H2 · Guard-rails (/freeze, /careful, /tdd) protect nothing outside the JOCA repo.**
The `settings.json` with the hooks is project-scope of JOCA_Brain; the install never merges into `~/.claude/settings.json`. In any target project (or via JOCA_OS), the 5 guard-rail skills are prose with no enforcement. Aggravating factor: in the public checkout, the `<JOCA_ROOT>` placeholder leaves the 10 hooks inert until /install (joca-doctor already detects this).
→ Install the hooks block in `~/.claude/settings.json` (the paths are already absolute) and document the scope.

## 🟠 HIGH (selection — 18)

### Backend JOCA_OS
- **PTY leak per automation:** each worker node run opens a session that never closes (`runner.ts:73-84`) → an hourly automation exhausts the 30 sessions in ~30 runs and EVERYTHING stops creating workers. Reuse the worker per automation or close it after N runs.
- **A bare Enter does not count as an answer** (`session-manager.ts:334`): answering a confirmation menu with Enter alone does not arm `notifyOnIdle` → `waitForUserAnswer` only resolves at the 24h timeout with the work already done.
- **Done-by-silence with no judge in the automations:** the runner captures a partial tail on pauses >1.5s and carries the pipeline on as "ok" (`runner.ts:80-84`) — the engine has a judge, the runner does not.
- **`moveTask` never re-compacts the source column** (`tasks/store.ts:143-149`, confirmed dead code) → duplicate orders → ambiguous ordering of the queue.
- **The scheduler decides retry/nextRun with a stale snapshot** (`scheduler.ts:30-59`): editing/disabling an automation during a long run is trampled at the end; PATCH does not reset retryCount.
- **`/cli-tools` blocks the event loop for up to ~45s** (`cli-capabilities.ts`: up to 9 execSync with an interactive shell, with no cache) — the WS and the PTYs freeze.
- **`pty.write` in timers with no guard** (`session-manager.ts:113,209,337`): a session dead between the scheduling and the callback → uncaughtException → backend down along with every PTY.
- **Zombie state after a restart:** `em-execucao` tasks and `running` automations stay that way forever after a crash — the boot does not sweep them.
- **SSRF in the http node + shell injection via `{{input}}`** (`runner.ts:94-108`): on a VPS the http reaches metadata endpoints; remote input interpolated into the shell line.

### Frontend JOCA_OS
- **Expired token → white-screen crash:** the fetches do `r.json()` without `r.ok` (`App.tsx:124` and 4 more) → `{error}` goes into `setProjects` → `.filter` blows up. It needs a central `fetchJson` + 401 → LoginScreen.
- **WS rejected by auth → infinite reconnect loop at 2s** with no backoff and no way out (`useSessionSocket.ts:205-211`).
- **Reconnect does not re-sync the terminals** — output emitted during the disconnection disappears from xterm; on mobile (socket suspended in the background) it is the normal case, not the exceptional one.
- **Input silently discarded** with a closed socket (`send()` is a no-op with no indication).
- **Drag-and-drop 100% inoperable on touch** — Kanban and reordering use HTML5 `draggable` → moving tasks on a phone is impossible.
- **Right panel nonexistent <860px** (`App.css:5640-5644`): Settings, Files, Toolkit — including the heartbeat UI — do not exist on a phone.

### Brain / docs
- **GEMINI.md/AGENTS.md bridges static and wrong:** they list MCPs that no longer exist (blender/firecrafl/huggingface), "Caveman-full" vs the real "Caveman Lite", v1 pipelines; the generator computes the real inventory and never uses it (`compile-bridges.sh:156-159`, dead code). Commands (27) are not mirrored in any bridge.
- **Phantom references en masse:** `.claude/product-marketing-context.md` (14 marketing skills), 9 `deep-research` scripts/templates (the agent is going to invoke nonexistent Python), `memory/knowledge/` (destination of /know), `memory/feedback/{archive,proposals}/` (destination of /upgrade-joca), `memory/profile.md` (referenced by soul.md in ALL sessions).
- **9 agents load skills that instruct `Agent(spawn)`** — impossible from a subagent (1-level rule). Reformulate to the dual pattern "main loop: Agent(...) / subagent: returns a suggestion" that chaining.md already defines.

13. **package-lock.json in .gitignore** + `npm install` on update → non-deterministic dependencies on every update. Version the locks + `npm ci`.
14. **sw.js:** the cache grows without limit between deploys (manual version); passive update (it never calls `registration.update()`); iOS with no icon (apple-touch-icon points to an SVG).
15. **Heartbeat:** the alert is repeated on every cycle with no memory of the last alert (nag loop); a manual beat ignores the `running` flag; old errors count as an anomaly forever.
